# 服务器接入步骤

先将项目同步到 https://github.com/To-Be-Want/Chrismas-tree，再从服务器拉取。GitHub仅保存源码和网页资源；运行中的祝福数据库与管理员凭据留在服务器，不会随Git上传。

## 第一步：确认服务器环境

通过云平台网页终端或SSH进入计划部署的Ubuntu环境。先只运行下面的只读检查，不安装软件、不重启原项目：

```bash
cat /etc/os-release
id -un
command -v git node npm nginx
node --version
npm --version
ss -ltn
systemctl is-active nginx
```

某项提示“未找到命令”也可以，记录结果即可。把上述输出提供给项目维护者；不要发送密码、私钥、`.env`、完整历史记录或其他项目配置。

## 第二步：拉取独立副本

确认Git可用、仓库已同步后，可在自己的用户目录下拉取一份副本，这不会更改原项目：

```bash
mkdir -p "$HOME/apps"
git clone https://github.com/To-Be-Want/Chrismas-tree.git "$HOME/apps/christmas-tree"
cd "$HOME/apps/christmas-tree"
bash deploy/check-server.sh
```

如果目录已经存在，Git会拒绝克隆；不要删除目录或覆盖它，先检查是不是已有部署。若服务器连不上GitHub，先排查访问，不要关闭证书校验或把访问令牌写入URL。

## 后续部署

根据环境检查结果选择独立目录、Node路径、内部端口和访问入口，再按README中的Nginx/systemd配置部署。现有项目即使不常用，也默认保留；不占用它的端口，不覆盖它的站点配置。

首次部署不等于“只连接仓库”：还需要安装依赖、构建、设置管理密码、保持Node服务运行、配置访问入口和保存数据。之后更新可以从此仓库拉取，但应先备份数据，在构建及测试成功后再重启圣诞树自己的服务。

先完成环境检查，再确定访问方式和域名/HTTPS方案；此文不预设80/443端口空闲。
